Key Design Decisions

Why This Design?

1. Different from Daily Calendar

Unlike daily2 which focuses on single-conversation daily summaries, collective memory is designed for cross-conversation analysis. The timeline shows patterns across multiple conversations, and clusters group related memories regardless of which conversation they came from.

2. Multi-Day Span Support

The timeline is organized by periods (weeks/months) rather than individual days, making it easier to see longer-term patterns and multi-day conversations that span across calendar boundaries.

3. Source Tracking

Each memory cluster shows source conversations as chips, making it clear which conversations contributed to each memory and enabling cross-referencing.

4. Real-Time Insights

The right panel provides automated insights - key highlights, detected patterns, trending topics, and recent activity - giving users immediate value without manual analysis.

5. Multiple View Options

Users can switch between Timeline (chronological), Clusters (topic-based), and Network (relationship-based) views to analyze memories from different perspectives.

Implementation Priority

  • Basic three-column layout with filters, timeline, and insights
  • Time period organization (weeks/months)
  • Memory cluster display with sources
  • Basic filtering by date range and conversations

Phase 2: Enhanced Features

  • Advanced filtering (topics, memory types)
  • Search functionality
  • Real-time insights panel
  • Statistics and metrics

Phase 3: Alternative Views

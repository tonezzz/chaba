# Chrome Remote Desktop (CRD) — Default Linux Install

Default procedure for adding a Linux machine to Tony's Chrome Remote Desktop fleet.
Reference installs: `tony-dell`, `mn01` (both registered under `tonezzzz@gmail.com`, XFCE session).

> Provenance: migrated 2026-09-26 from `devin-kb` commit `8276c25`
> (originally committed as `e601064` by session fancy-aries). devin-kb is
> archived on GitHub, so the doc could not be pushed there; chaba `docs/kb/`
> is now the canonical home.

## Steps

### 1. Install the package

```bash
wget -q https://dl.google.com/linux/direct/chrome-remote-desktop_current_amd64.deb -O /tmp/crd.deb
sudo apt install -y /tmp/crd.deb
```

(Or remotely: `ssh <host> 'wget -q ... -O /tmp/crd.deb && sudo apt install -y /tmp/crd.deb'`)

### 2. Configure the desktop session

CRD needs a session launcher file. Fleet default is XFCE:

```bash
echo "exec /usr/bin/startxfce4" > ~/.chrome-remote-desktop-session
```

Requires `startxfce4` to be installed (`xfce4-session`). Check `/usr/share/xsessions/` for alternatives.

### 3. Register the host (needs a browser, one time per machine)

The auth code can only be generated by a human signed into the Google account:

1. In Chrome signed into **tonezzzz@gmail.com**, open <https://remotedesktop.google.com/headless>.
2. "Set up another device" → Begin → Authorize → copy the shown Debian command.
3. Run it on the target host (as the login user, not root). Add `--display-name=<hostname>` and a temporary `--pin=<6+ digits>` so it runs non-interactively:

```bash
DISPLAY= /opt/google/chrome-remote-desktop/start-host \
  --code="<code from page>" \
  --redirect-url="https://remotedesktop.google.com/_/oauthredirect" \
  --display-name=<hostname> --pin=<temp-6-digit-pin>
```

This writes `~/.config/chrome-remote-desktop/host#<hash>.json` and enables/starts
`chrome-remote-desktop@<user>.service`.

### 4. Reuse the fleet PIN instead of a new one (optional but preferred)

The PIN is stored as `host_secret_hash` in the host JSON. Copy the value from an
existing host (e.g. tony-dell) into the new host's JSON — the PIN then matches
without ever typing it:

```bash
# on the source host, read the hash; on the new host, patch it in, then:
sudo systemctl restart chrome-remote-desktop@<user>.service
```

### 5. Verify

```bash
systemctl status chrome-remote-desktop@<user>.service   # active (running), enabled
```

`xdpyinfo: unable to open display ":20"` in the journal is normal — CRD spawns its
own X display on first connect. The machine should show **Online** at
<https://remotedesktop.google.com/access>.

## Notes

- Package is `chrome-remote-desktop` (Beta channel); `apt` always fetches current.
- Service is a per-user systemd instance: `chrome-remote-desktop@<user>.service`.
- Host type: `single-process` (default, X11). `gdm-managed` exists but only for
  GNOME 49+ Wayland — not the fleet default.
- Never commit host JSON files or PINs; the JSON contains `oauth_refresh_token`
  and `private_key`.
- Related docs in this repo: `docs/kb/chrome-remote-desktop-profile-management.md`
  and its `-troubleshooting` / `-technical` / `-problem` companions.

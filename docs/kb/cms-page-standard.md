# CMS page standard — landing-page format

Every `ada-cms-pages` document should open like a mini landing page:
the reader gets the verdict and the newest developments without
scrolling, and can jump to detail via section links.

## Required structure

```markdown
# Title — matches meta.title

**Status: one-line verdict a reader can act on.**

## Latest

- **YYYY-MM-DD** — newest development first, one line each (≤5 entries;
  roll older ones into a History/archive section at the bottom).

Sections: [Section A](#section-a) · [Section B](#section-b)

## Section A / Section B ...

## History — earlier dated entries, newest first (optional)

*Generated by <writer> · <date>Z · sources: <n>*  ← provenance footer
```

## Rules

1. **Status line first** — bold, immediately under the H1. Answers
   "what's the current state?" in one sentence.
2. **`## Latest` before detail** — reverse-chronological, dated bullets.
   Updated pages put the change here, not buried mid-document.
3. **Section links** — one line of markdown anchor links right after
   Latest when the page has >2 sections.
4. **Media welcome** — charts/diagrams embedded as `![alt](url)` with
   assets served from `stacks/web/public/apps/reports/` (reachable at
   `https://tony-dell.taila0626a.ts.net/apps/reports/<file>`).
   Benchmarks should always include a graph, not just a table.
5. **Provenance footer** — `*Generated by … · sources: …*` (audit rule
   R2); generated reports also need `meta.sources` (R1).
6. **Meta** — full schema block: kind=page, slug, title, format,
   updated, bank, scope, status, source, written_by, subject,
   attribute, valid_from, last_verified.

## Audit

`scripts/ada/cms-audit.py` enforces the older A/R/N/S rules plus:
- `status: stub` or `status: archived` skips the A1 thin check — mark
  intentional stubs instead of leaving empty pages failing.
- `A5_EXEMPT` covers docs that describe the placeholder rule itself
  (`cms-audit-report`, `document-audit-policy`).

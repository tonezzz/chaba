# SSOT Configuration Save Workflow

**Abstract**: Use this runbook after changing service endpoints, MCP server settings, or health checks. It keeps the YAML SSOT, MDDB search index, live runtime configs, and KB documentation in sync.

## Overview

The authoritative SSOT files live in `docs/ssot/`. MDDB semantic search is built from them, and runtime configs such as `~/.config/devin/mcp_config.json` and `stacks/web/docker-compose.yml` are derived from them. This workflow ensures every change is validated, indexed, backed up, and committed in the right order.

## Key Files

| File | Purpose |
|------|---------|
| `docs/ssot/infrastructure/ssot.mcp.yml` | MCP server and profile definitions |
| `docs/ssot/infrastructure/ssot.health.home.yml` | Home network health checks and host mappings |
| `docs/ssot/infrastructure/ssot.health.mobile.yml` | Mobile/external health checks |
| `docs/ssot/ssot.validation-patterns.yml` | Validation rules and hostname standards |
| `docs/ssot/ssot.index.yml` | Registry of all SSOT files |
| `~/.config/devin/mcp_config.json` | Live Devin MCP config (derived) |
| `scripts/ssot-validate-sync.sh` | YAML validation and consistency report |
| `scripts/backup-configs.sh` | Live config backup to `docs/backups/configs/` |

## Operational Procedure

### 1. Edit SSOT first

- Modify `docs/ssot/infrastructure/ssot.mcp.yml` and/or `ssot.health.home.yml`/`ssot.health.mobile.yml`.
- Prefer `.local` hostnames such as `tony-dell.local` over IP addresses.
- Exceptions: health-check placeholders like `[CURRENT-IP]`, explicit network documentation, and Docker network aliases where `.local` DNS is not resolvable inside the container.
- Register any brand-new SSOT file in `docs/ssot/ssot.index.yml`.

### 2. Validate

```bash
bash scripts/ssot-validate-sync.sh
```

Fix any YAML syntax, missing required fields, or duplicate labels reported in `docs/ssot/validation-report-*.txt`.

### 3. Sync to MDDB

SSOT is normally auto-synced by the file watcher, but to force an immediate update:

```bash
python3 scripts/sync-ssot-to-mddb.py
```

If the watcher is down, update the relevant MDDB document directly with the `mcp_call_tool mddb add_document` call.

### 4. Reflect in runtime configs

- Update `~/.config/devin/mcp_config.json`, `stacks/web/docker-compose.yml`, or other runtime files from the SSOT values.
- Run the backup script to snapshot live configs:

```bash
bash scripts/backup-configs.sh
```

Backups are written to `docs/backups/configs/` and are excluded from git by `.gitignore`.

### 5. Cross-link docs

- If the change introduces a reusable decision or new pattern, add a `decisions:` block in the SSOT or a KB entry in `docs/kb/`.
- Use `related_files` in the SSOT `config` block and `related` in KB frontmatter.

### 6. Commit

```bash
git status
git diff
git commit -m "docs: update ssot.mcp and health for tony-dell data migration"
```

Allowed prefixes include `feat`, `fix`, `docs`, `chore`, and `refactor`. Keep the message to one sentence.

### 7. Verify

- `mcp_list_servers` and `mcp_list_tools` to confirm Devin picks up new MCP settings.
- `health-check` or `mcp_net` on the relevant host to confirm services are listening.
- `mcp_call_tool mddb semantic_search` to confirm SSOT is indexed.

## Troubleshooting

### MDDB search returns old values

- Force a sync with `scripts/sync-ssot-to-mddb.py`.
- Check the watcher service: `systemctl --user status ssot-sync.service`.

### Validation reports IP violations

- Review the line. Some IPs are intentional (Docker aliases, health placeholders, network docs).
- For other cases, replace with a `.local` hostname.

### Runtime config does not match SSOT

- Regenerate or edit `~/.config/devin/mcp_config.json` from the SSOT profile.
- Run `scripts/backup-configs.sh` after the live config is final.

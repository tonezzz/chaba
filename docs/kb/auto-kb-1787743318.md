# Home Assistant Camera Additions — USB, VSTARCAM, Z-IoT, and Frigate Search

**Abstract**: This session added a USB camera and a VSTARCAM IP camera to Home Assistant running in Podman on `tony-dell`, patched the `ffmpeg_camera.py` integration, and investigated a `Z-IOT CAM` and a Frigate `vstarcam` that could not be integrated without hardware flashing or network changes.

## Overview

Home Assistant was already running in a Podman container on `tony-dell`. The work focused on integrating the local USB webcam, discovering an existing local IP camera, and trying to add an additional `Z-IOT CAM` and a camera found in the Frigate configuration.

## Key Files

| File | Purpose |
|------|---------|
| `~/.config/home-assistant/configuration.yaml` | Home Assistant configuration with `ffmpeg` camera entries |
| `~/.config/home-assistant/patches/ffmpeg_camera.py` | Patched `FFmpegCamera` class adding `unique_id` and conditional `CameraEntityFeature` |
| `~/.config/containers/systemd/home-assistant.container` | Quadlet container config passing `/dev/video*` devices and patched files |
| `/home/tony/CascadeProjects/chaba/frigate/config.yml` | Frigate NVR camera definitions, including `vstarcam` at `192.168.1.41` |

## Implementation Details

### USB Camera

- Added `AddDevice=/dev/video0:/dev/video0` and `AddDevice=/dev/video1:/dev/video1` to the Quadlet container.
- Configured `ffmpeg` camera entry:
  ```yaml
  - platform: ffmpeg
    name: tony_dell_usb
    input: -f v4l2 -i /dev/video0
    extra_arguments: -ss 0
  ```

### VSTARCAM IP Camera (192.168.2.65)

- Discovered with `nmap`; credentials supplied by user: `admin` / `tonytony`.
- Verified with `ffprobe` / `ffmpeg` using:
  ```
  rtsp://admin:tonytony@192.168.2.65:10554/tcp/av0_1
  ```
- Added to `configuration.yaml` as `ip_cam_65`.

### FFmpeg Patch

- `~/.config/home-assistant/patches/ffmpeg_camera.py` added `self._attr_unique_id = f"{config[CONF_NAME]}_ffmpeg"`.
- Conditionally enabled `CameraEntityFeature.STREAM` only for IP cameras, disabling it for `/dev/video*` devices to avoid `Resource busy`.

## Operational Findings

### Z-IOT CAM

- Device IP on `tony_wifi_2.4g`: `192.168.1.33` (`3e:8a:c0:fb:b1:2c`).
- Firmware: `TXW817_G_V1.0.1.4` on TXW817-810 SoC.
- Scanning showed no open RTSP/HTTP/ONVIF ports. Stock firmware is cloud-only via the `Z IOT CAM` app.
- Open firmware `OpenTXW81X` would expose `rtsp://{ip}:7070/webcam`, but requires physical flash with a C-SKY programmer / STM32 Blue Pill.
- User declined flashing. **Cannot be added to Home Assistant as-is.**

### Frigate `vstarcam` (192.168.1.41)

- Found in `/home/tony/CascadeProjects/chaba/frigate/config.yml`.
- Credentials: `admin` / `tonytony`, RTSP path: `rtsp://admin:tonytony@192.168.1.41:10554/tcp/av0_1`.
- Reachable from `tony-omen` but **not from `tony-dell`** where Home Assistant runs.
- Frigate container was not running. To use it, would require starting Frigate with `go2rtc` restreaming or a network route.

## Troubleshooting

### Issue: `TypeError: argument of type 'int' is not a container or iterable`
- **Symptoms**: Camera entity fails to load.
- **Cause**: `_attr_supported_features = 0` (int) is tested with `CameraEntityFeature.STREAM in`.
- **Solution**: Use `CameraEntityFeature(0)` for disabled features.

### Issue: `haffmpeg` timeout / zero-byte images
- **Symptoms**: `Timeout while waiting of FFmpeg` and empty captures.
- **Solution**: Reverted a manual `haffmpeg_tools.py` timeout patch and restarted the container; clean restart resolved it.

### Issue: Z-IoT camera has no open ports
- **Symptoms**: `nmap` shows all standard camera ports closed/filtered.
- **Cause**: Stock TXW817 firmware is cloud-only.
- **Solution**: Only fixable by flashing open firmware (declined).

## Commands Used

```bash

# Test RTSP stream

# Test JPEG capture
ffmpeg -y -hide_banner -loglevel error -rtsp_transport tcp -i "rtsp://..." -an -frames:v 1 -c:v mjpeg -ss 0 -f image2pipe - | wc -c
```

# dispatch-outcome: board-api-commit-outside-lock

## What changed

`scripts/board/board-api.py` — moved the per-write `git add`+`git commit`
out of `/tmp/board-api.lock`, which was the root cause of the 2026-11-19
lock convoy (hold_max 118.7s, 503 storm 08:33-09:02):

- `save()` now calls `_queue_commit()` inside the locked section: records
  repo-relative dirty paths (+ `.ref-seq` when present) + label in
  `_pending_commits`. No subprocesses under the flock — the locked
  section is card-YAML read-modify-write only.
- New `_commit_loop` daemon worker (same shape as `render_async`): waits
  on `_commit_flag`, debounces `BOARD_API_COMMIT_DEBOUNCE_S` (0.4s) so
  bursts coalesce into the fewest commits, drains pending paths, joins
  labels, commits once per drain cycle.
- `_commit_paths()` does the git work OFF the flock: LOCK_NB probe
  (`_card_lock_held`) defers while a request RMW or git-safe-pull's whole
  pull+autostash+pop phase holds the card flock — never holds the flock
  across git ops; keeps the rebase-merge/rebase-apply/MERGE_HEAD/
  CHERRY_PICK_HEAD gitdir guard; per-path `git add` fallback on
  "did not match" so one vanished queued path can't drop the batch;
  transient failures (index.lock, mid-rebase, lock held) requeue and
  retry every `BOARD_API_COMMIT_RETRY_S` (5s) up to
  `BOARD_API_COMMIT_MAX_TRIES` (60), then drop to the kanban-commit
  sweep with a stderr note — same durability model as before.
- `commit_pending_flush(timeout)` for tests/drains; `commit_async()`
  nudged by `_queue_commit`, the do_POST tail, and `_append_comms_note`.
- `BOARD_API_COMMIT=0` off-switch unchanged.
- Comment-only updates in `git-safe-pull.sh`, `kanban-commit.sh`,
  `tests/test-kanban-commit.sh` to describe the new lock contract;
  `test_board_api_reads.py` mock renamed `_commit_write`→`_queue_commit`.
- Selftest extended: deferred commit lands, 3-write burst coalesces,
  BOARD_API_COMMIT=0 dirty path, mid-rebase defer + retry-lands,
  non-repo paths filtered.
- SSOT trail: `docs/ssot/jobs/infrastructure/2026-11-19-board-api-commit-outside-lock.yml`.

lessons:
- git add is all-or-nothing on pathspecs — one queued path that's
  untracked AND deleted before a deferred commit runs fails the whole
  batch with "did not match"; stage survivors per-path or the batch is
  silently dropped.
- /tmp/board-api.lock.repo is host-global — a sandboxed board-api copy
  started for smoke testing overwrites the live sentinel; restore/remove
  it afterward or foreign-checkout pulls read the wrong repo.
- git-safe-pull holds the card flock across pull+autostash+pop, so a
  LOCK_NB probe is enough to keep post-lock commits from racing the
  autostash window without re-serializing them under the flock.
- Selftest's guard-save queues the real repo's `.ref-seq` because
  CARD_DIR is restored before the git section — commit-worker pending
  dicts keyed by repo-relative path can mix rels from different REPO
  contexts; only a test artifact but it exposed the batch-add drop.

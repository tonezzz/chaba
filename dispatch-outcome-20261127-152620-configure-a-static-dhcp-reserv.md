lessons:
- A dispatch branch that "finished ok" can still strand on a generated-file conflict — `docs/ssot/ssot.dev-system.assessment.yml` is regenerated by a background producer and conflicts on `last_reviewed`/counts whenever two branches touch it in the same window (this is what blocked attempt 1's auto-merge).
- For a failed-merge retry, merge the OLD dispatch branch into the NEW one rather than re-doing the work — the card's `task_id_for` probes only the newest devin-task id, so the new branch must carry the old one's commits for the content to land.
- The active NM connection on omen's eno1 is named `eno1`, not `netplan-eno1` (that profile exists but is inactive/auto) — check `nmcli con show --active` before trusting profile names in docs.
- `docs/ssot/ssot.dev-system.assessment.yml` is a per-host generated file that a background producer rewrites inside dispatch worktrees — every dispatch branch that carries a delta on it is a merge-conflict time bomb. Fix: `git checkout <merge-base> -- <file>` + `git update-index --skip-worktree <file>` before finishing; the checkpoint then can't recommit the churn.
